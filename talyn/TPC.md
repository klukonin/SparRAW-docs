# Мощность TX и замкнутая подсистема TPC в Talyn (QCA6436)

Разбор прошивки **Talyn 7.5.3.115** (fw, Ghidra, имена по лог-строкам; метка **[код]**) и модулей пакета RouterOS `wireless`
(драйвер `wil6210.ko` и бинарный демон `nova/bin/wireless`).
Сопоставление со статической открытой регулировкой мощности чипа Sparrow — [../research/TX-POWER.md](../research/TX-POWER.md).

---

## 1. Архитектура замкнутой системы TPC в Talyn

В отличие от Sparrow, где мощность передачи рассчитывается исключительно по статической таблице усилений (board-файл, строка 7)
и цифровому аттенюатору (`0x8840f8 … 0x884128`), чип Talyn (QCA6436) реализует полноценную **аппаратную замкнутую систему
регулировки мощности передачи (Closed-Loop Transmit Power Control, TPC)** с измерением реальной излучаемой мощности
встроенными РЧ-детекторами TSSI (Transmit Signal Strength Indicator).

### Программные модули прошивки:
- `calib_tx_power` (27 лог-строк): общая калибровка мощности, адаптивный выбор оптимального профиля усиления («lineup»).
- `hw_flows_tx_power_sens`: организация измерительных циклов и сбор отсчетов датчиков.
- `hw_drivers_tlna2_rfc`: прямой доступ к аппаратным регистрам радиочастотного интерфейса TLNA2.
- `linear_power`: пересчет измеренных напряжений детекторов в шкалу дБм и линеаризация тракта.
- `time_averaging`: сглаживание измерений во времени и ограничение среднего излучения (`time_averaging_update_pout_post_tpc`).

## 2. Аппаратный детектор мощности (TSSI) в РЧ-блоке TLNA2

Радиомодуль **TLNA2** («Talyn Low-Noise Amplifier v2» / Marlon-R-v2) содержит интегрированные детекторы радиочастотной мощности
на каждом антенном элементе фазированной решетки:

### Процедура запуска измерения TSSI **[код]**:
1. **Инициализация тракта измерения**: последовательная запись в РЧ-регистры `0xb4`, `0x1d8`, `0x1a0`, `0x1a4`, `0x1bc`, `0x1b4`, `0x1ac`.
2. **Выбор измеряемых антенн**: РЧ-регистр `0x3a4 + 4·(антенна / 2)` (конфигурация пар антенных элементов).
3. **Старт выборки (Trigger)**: запись `1` в РЧ-регистр **`0x214`**.
4. **Контроль завершения**: опрос РЧ-регистра `0x210 != 0` и бита 0 регистра **`0x20c`**.
5. **Считывание оцифрованного напряжения (ADC Output)**:
   $$\text{Адрес} = 0x218 + 4 \cdot \text{антенна} + 0x80 \cdot k$$
6. **Сброс и реконфигурация**: РЧ-регистры `0x398`, `0x1dc`, `0x52c`.

### Математическая модель пересчета $V_{\text{out}} \to P_{\text{out}}$
Напряжение детектора $V_{\text{out}}$, оцифрованное АЦП РЧ-блока, компенсируется по таблицам DC-смещения (LUT в ОЗУ по адресам
`0x857710` и `0x857790`) функцией `tx_power_get_dc_lut_val`, после чего преобразуется в реальную мощность $P_{\text{out}}$
в десятых долях дБм (0,1 дБм) функцией `tx_power_vout_to_pout`:

$$P_{\text{out}} [0,1\text{ дБм}] = \left(\frac{V_{\text{out}} \cdot 10}{2^n}\right) - 0x280$$

Константа вычитания **$0x280$** (640 в десятичной системе) соответствует смещению шкалы на **64,0 дБм**, приводя оцифрованное
значение АЦП к реальной физической мощности излучения с учетом коэффициента направленного действия решетки.

### Участие микрокода (ucode) в выборках TSSI
Замеры мощности синхронизируются с кадрами передачи через команды LMAC `0x46`, `0x47` и `0x60` (`tx_power_sens_send_msg_*`).
Конфигурация замера занимает 0x6c байт, шаблоны размещены в ОЗУ по адресам `0x808338`, `0x8082f8`, `0x808420`.
Результаты выборок накапливаются в циклическом кольце памяти по адресу **`0x8578dc`** (записи размером по 0x18 байт).
Лучший результат выборки фиксируется функцией `tx_power_gain_sample_result` и заносится в рабочую таблицу профилей `tx_power_fill_lineup_entry`.

## 3. Динамическое управление усилением по MCS на лету

Функция `calib_tx_power_set_gain_idx` выбирает вычисленный оптимальный индекс профиля усиления и применяет его ко всем схемам модуляции
через цепочку вызовов `abif_set_mcs_range_all` $\to$ `abif_set_mcs_range` $\to$ `abif_set_mcs(mcs, index, table)`:

- **Таблица 0**: регистры `0x8891dc + 4·mcs` (MCS 0…15, поле `[4:0]`).
- **Таблица 1**: регистры `0x88919c + 4·mcs` (MCS 0…15, поле `[4:0]`).

### Диапазоны MCS (`abif_set_mcs_range`, режимы 0/1/2):
- **Низкие скорости**: MCS 0…5 (или 1…5 для SC);
- **Средние скорости**: MCS 6…9 (или 7…11);
- **Высокие скорости / EDMG**: MCS 10…12 (или 12…15). Функция `calib_tx_power_set_gain_idx_sel` позволяет задавать индекс для EDMG независимо.

**Ключевое преимущество архитектуры**: аппаратный передатчик Talyn считывает индекс строки усиления непосредственно из регистра,
соответствующего MCS передаваемого пакета. Это позволяет изменять мощность излучения **попакетно, в темпе эфира**, без разрыва
соединения и без перезапуска РЧ-тракта.

## 4. Хостовое управление пределом мощности: WMI 0xa20

Для ограничения максимальной средней мощности излучения хост может отправить команду WMI:
- **`WMI_TPC_SET_MAX_AVG_TX_POWER` (0xa20)** $\to$ обработчик `wmi_tpc_set_max_avg_tx_power`:
  - Входной параметр: знаковое 8-битное целое `s8 limit` в диапазоне от **-100 до +100 дБм** (проверка `limit > -101 && limit < 101`).
  - Применяется через `time_averaging_set_delta_limit`.
  - Прошивка возвращает событие `0x1a20` со статусом (0 — успешно, 1 — значение вне диапазона).
  *На чипах Sparrow 6.2 данная команда отсутствует.*

## 5. Сравнение архитектур TPC: Sparrow vs Talyn

| Характеристика | Sparrow (QCA6310/6320/6335) | Talyn (QCA6436) |
|---|---|---|
| **Тип управления** | Open-Loop (разомкнутый контур по калибровке) | **Closed-Loop (замкнутый контур с TSSI)** |
| **Датчик мощности TSSI** | Отсутствует (РЧ 0x218..0x2a0 — вторая таблица усилений) | **Есть в TLNA2** (РЧ 0x20c, 0x210, 0x214, 0x218+4*ant) |
| **Регистры мощности по MCS** | `RFC_TX_POWER_TBL` 0x8891b4..e4 (13 слов, MCS 0..12) | 2 таблицы: `0x8891dc + 4*mcs` и `0x88919c + 4*mcs` (MCS 0..15) |
| **Цифровой аттенюатор** | `0x8840f8 … 0x884128` (12 слов по MCS) | `0x8840f8 … 0x884128` (чтение `hw_sys_api_get_digital_atten`) |
| **Хостовая команда WMI** | Отсутствует (только `patchBoardFileRFRegs`) | **`WMI_TPC_SET_MAX_AVG_TX_POWER` (0xa20)** |
| **Реакция на температуру** | Только программный опрос термодатчика (0x80e) | Аппаратная термокомпенсация в цикле TPC |

## 6. Драйвер wil6210 в RouterOS и принудительное отключение TPC

Анализ драйвера `wil6210.ko` из состава RouterOS 6.48.6 (arm64) показывает, что разработчики MikroTik **сознательно отключают
встроенную калибровку TPC прошивки Talyn**:
1. В обработчике поднятия сетевого интерфейса (в районе вызова `netif_carrier_on`), если чип идентифицирован как Talyn (`hw_type == 2`):
   - Проверяется указатель в объекте драйвера по смещению `+0x26020`.
   - В лог ядра выводится сообщение: `disable TX_POWER calibration`.
   - В память устройства по адресу `[указатель + 0x14]` записывается значение **`1`** (`writel`).
2. Причина отключения: RouterOS реализует собственное статическое профилирование мощности через патчинг board-файла:
   - В секции РЧ-регистров board-файла (ключи `0xa000900d`, `0xc00c900e`, `0xc00c900d`) драйвер находит строку 7 и переключает байт по адресу `0x8ffff2` между 0 и 255 («change slow control»).
   - Изменение мощности `tx-power` в CLI RouterOS транслируется в вызов `patchBoardFileRFRegs` и требует полного перезапуска радиоинтерфейса.
