# Окно A-BFT и таблицы расписания BI (4.1.0.1000)

«Длинный» BTI, который раз в несколько интервалов маяка виден в отчёте `MAC_MON`, — это
окно A-BFT. Его период и длина задаются полями конфигурации BI в данных ucode и
меняются с хоста записью в память, без патча прошивки. Ниже — опыты на стенде и
разбор генератора таблиц, из которых берётся длина окна.

Раскладка конфигурации BI `0x801438` (host `0x941438`) и имена её полей —
[4.1/docs/BEACON-CONFIG.md](https://github.com/klukonin/SparRAW-firmware/blob/main/4.1/docs/BEACON-CONFIG.md);
соответствие полям стандарта (`n_bis_abft`, `fss`, `abft_length`) и опыт с
`abft_length = 7` —
[docs/STANDARD-MAPPING.md](https://github.com/klukonin/SparRAW-firmware/blob/main/docs/STANDARD-MAPPING.md);
ответчик A-BFT и безролевой линк —
[docs/ROLELESS-LINK.md](https://github.com/klukonin/SparRAW-firmware/blob/main/docs/ROLELESS-LINK.md);
значения ячеек расписания при смене периода BI —
[docs/MAC-COMMANDS.md §9.1](https://github.com/klukonin/SparRAW-firmware/blob/main/docs/MAC-COMMANDS.md#91-период-маяка).

## 1. Где открывается окно **[код]**

В конце `bti_worker__bti_transmitter_beacon_sweep_flow` (uc 0x923de0), после
развёртки секторов:

```c
g_801e69 = 1 - g_80142c;            /* 0x80142c — счётчик периода           */
if (1 < g_80142c) g_801e69 = 0;     /* => 1 только при нулевом счётчике     */
g_801e82 = 1;
bi_cfg__tick_counters();            /* перезарядка счётчика из cfg[+0x04]   */
if (g_801e69 == 0) {
    /* ожидание бита в регистре MAC */
} else {
    /* окно A-BFT: последовательность в кольцо команд MAC */
    mac_cmd(0x4f, 0x801b04 + 0x1ef);
    mac_cmd(0x50, 0x801afc + 0xa5);
    mac_cmd(0x51, 0x801b00);
    ...
}
```

Тот же байт `0x801e69` включает путь ответчика A-BFT: `bi_manager` (uc 0x926858)
вызывает 0x931050 → `abft_responder_worker` (uc 0x92c594) только при
`0x801e69 != 0`. Байт взводится на короткое время раз в N интервалов, поэтому
одиночное чтение памяти обычно показывает 0.

## 2. Таблицы расписания **[код + железо]**

```
bi_build_schedule_tables  uc 0x927f00   (инициализация, программная плавающая точка)
        │  три таблицы u16 в 0x802030…0x802077
        ▼
ucode_cmd__bi_config      uc 0x932f8c   (LMAC 0x0b), индекс = cfg[+0x07] (fss)
        ▼
0x801afc = A[idx]    0x801b00 = B[idx]    0x801b04 = (cfg[+0x0a] + 1) · B[idx]
```

Генератор: цикл из 12 итераций `i = 4…15` в double через библиотечные
подпрограммы компилятора — `softfloat_int_to_double` 0x920464,
`softfloat_df_mul` 0x9204ac, `softfloat_df_add` 0x920974,
`softfloat_double_to_short` 0x9210e4. Константы 14.9, 0.9, ≈3011.6, 1485.
Рабочая величина растёт на `0xa5 + 0x99b = 2624` за итерацию.

| таблица | адреса | значения (i = 4…15) |
|---|---|---|
| малая | 0x802030…0x802046 | 79, 95, 111, 127, 143, 158, 174, 190, 206, 222, 238, 254 |
| A | 0x802048…0x80205e | 12955 + 2624·k |
| B | 0x802060…0x802076 | 18936 + 2624·k |

Обращение идёт по базам 0x802040 и 0x802058 — на 4 элемента левее начала A и B,
так что индекс из конфигурации (4…15) используется без вычитания.

Малая таблица равна `(i+1)·14.9 + i + 0.9` при i = 4…15 — совпадают все 12
значений (79.4 → 79, …, 254.3 → 254). Это же совпадение различает две
подпрограммы: с умножением на месте сложения шаг таблиц не был бы постоянным.

Сверка со снимком ОЗУ (стенд, `cfg[+0x07] = 15` → элемент 11):

| ячейка | расчёт | в ОЗУ |
|---|---|---|
| 0x801afc | A[11] = 12955 + 2624·11 = 41819 | 0xa35b |
| 0x801b00 | B[11] = 18936 + 2624·11 = 47800 | 0xbab8 |
| 0x801b04 | (1+1)·47800 = 95600 | 0x17570 |

Обращения к малой таблице: 0x923f74 в `bti_transmitter_beacon_sweep_flow` и
0x92cb8c в `abft_worker_responder_funcs.cpp`.

## 3. Опыты на стенде **[железо]**

Узел AP, запись в ОЗУ ucode через debugfs `mem_write` (host-адреса `0x94xxxx`),
длительность BTI — из отчёта `MAC_MON`.

### 3.1. Период: `cfg[+0x04]` (0x80143c)

| значение | наблюдение |
|---|---|
| 4 (сток) | между длинными BTI ровно 4 интервала |
| 2 | строгое чередование «длинный — короткий», 25 разрывов по 2 |
| 1 | все BTI длинные, 59 разрывов подряд по 1 |

### 3.2. Длина: `0x801b04`

| 0x801b04 | прибавка к BTI |
|---|---|
| 95 600 (сток) | 585.0 мкс |
| 191 200 | 1135.4 мкс |
| 286 800 | 1691.3 мкс |

Зависимость линейная: предсказание третьей точки по первым двум — 1685.8 мкс при
измеренных 1691.3 (0.3 %). Наклон ≈ **172.8 единиц на микросекунду** (единица ≈
5.79 нс), свободный член ≈ 32 мкс — накладные расходы окна. В этом масштабе
B[idx] = 47 800 единиц ≈ 275 мкс, и `cfg[+0x0a] + 1` — число слотов A-BFT
(сток: 2 слота × 275 мкс = 550 мкс, +32 = 585).

### 3.3. `0x801afc` на длину не влияет

`0x801afc` (A[idx] = 41 819) уходит в команду MAC 0x50. Удвоение до 83 638 ничего
не меняет: короткий BTI 1365.9, длинный 1950.6, прибавка 584.8 мкс — как в стоке.

### 3.4. Параметр драйвера `abft_len`

Увеличение `abft_len` драйвера (до 6, с перезапуском hostapd) длину окна не
меняет: она задаётся `cfg[+0x0a]` и `B[idx]` из конфигурации ucode, а
`WMI_PCP_START.abft_len` в этот блок в 4.1 не переносится либо используется в
другом месте.

## 4. Рычаги с хоста

| рычаг | адрес (host) | эффект |
|---|---|---|
| `bi_mode = 2` | 0x941438 | снимает окно AW ([AW-WINDOW](AW-WINDOW.md)) |
| `cfg[+0x04]` | 0x94143c, байт 0 | период окна A-BFT в интервалах маяка |
| `0x801b04` | 0x941b04 | длина окна A-BFT |

Запись `abft_length = 7` в `cfg[+0x0a]` на работающем узле длину окна не меняет
([docs/STANDARD-MAPPING.md](https://github.com/klukonin/SparRAW-firmware/blob/main/docs/STANDARD-MAPPING.md)):
вероятно, потому что `0x801b04` вычисляется в хвосте `ucode_cmd__bi_config`, а не
при записи в конфигурацию **[гипотеза]**.

## Не установлено

* Единица длины. Шаг таблиц 2624 совпадает с длительностью кадра SSW в тактах MAC
  165 МГц (2624 такта = 15.9 мкс,
  [docs/BF-ENGINE.md](https://github.com/klukonin/SparRAW-firmware/blob/main/docs/BF-ENGINE.md)),
  что делает такт 165 МГц естественным кандидатом; измеренный наклон 172.8 ед/мкс
  отличается от него на ≈ 5 % **[гипотеза]**. Тогда B[idx] — длительность слота
  A-BFT при FSS = idx+1 кадров SSW.
* Роль A (`0x801afc`, команда MAC 0x50) и смысл малой таблицы (79…254).
* Смысл констант 3011.6 и 1485 во второй половине цикла генератора.
* Асимметрия длинного интервала между узлами (≈ 89 мс против ≈ 17 мс) —
  [docs/STANDARD-MAPPING.md](https://github.com/klukonin/SparRAW-firmware/blob/main/docs/STANDARD-MAPPING.md).
