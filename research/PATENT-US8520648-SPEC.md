децентрализованного биконинга, реализованного в прошивке wil6210 (рандомизатор отсрочки маяка).

## 2. Алгоритм (FIG. 5) — состояния станции в каждом beacon interval
```
502  Установить случайную задержку delay ~ U(0, RangeMax)
504  Дождаться начала BI (TBTT)
506  Приостановить декремент backoff-таймеров не-mmWave передач
508  Отсчитывать delay
510  Принят ли маяк от другой STA до истечения delay?
512    НЕТ  → передать СВОЙ маяк серией направленных передач (по секторам)
514    ДА   → отложить свой маяк до СЛЕДУЮЩЕГО BI
     → на следующем BI снова с 502 (новый случайный delay)
```

## 3. Параметры и формулы
| параметр | определение |
|---|---|
| `aCWminMMwaveIBSS` | мин. окно конкуренции ДЛЯ МАЯКОВ (отдельное от `aCWmin` для данных). Рекомендация патента: может быть ~1/6 от aCWmin (напр. aCWmin=31 → 5) |
| `B_Time` | длительность ОДНОЙ направленной передачи маяка |
| `SBIFS` | межкадровый интервал между секторными передачами |
| `MaxDirTransmissions` | макс. число направленных передач (≈ число антенных элементов/секторов) |
| `PlannedDirTransmissions` | запланированное число секторных передач на следующий BT |
| `BT` (Beacon Time) | окно от первой до последней секторной передачи маяка |

```
BT_Length = MaxDirTransmissions     × (B_Time + SBIFS)     (макс. подход, eq.3)
BT_Length = PlannedDirTransmissions × (B_Time + SBIFS)     (план. подход, eq.4)
RangeMax  = 2 × aCWminMMwaveIBSS × BT_Length               (eq.2)
delay     ~ Uniform(0, RangeMax)
```
**Пример из патента:** B_Time=80 мкс, PlannedDirTransmissions=4, SBIFS=0,
aCWminMMwaveIBSS=31 → RangeMax = 2·31·320мкс = 19.84 мс, средняя задержка **9.92 мс**.
(С aCWminMMwaveIBSS=5: RangeMax=3.2 мс, средняя 1.6 мс.)

## 4. Независимые/ключевые claims (сжато)
1. Установить delay **на основе характеристики направленной передачи маяка**;
   слушать в течение delay от начала BI; при отсутствии приёма — передать свои
   направленные маяки по истечении delay.
2. delay — СЛУЧАЙНЫЙ в [0, max].
3. max — на основе **первого** мин. окна конкуренции (для маяков), отличного от
   **второго** (для доступа к среде под данные).
4. При приёме чужого маяка — **воздержаться** от передачи маяков в этом BI.
5. Передачи — миллиметровые (mmWave).
6. Начало BI = **TBTT**.
7. Сеть = **IBSS** (Independent BSS).

## 5. Чего в патенте нет
Патент покрывает только рандомизированную отсрочку и прослушивание перед маяком. В нём нет
ATIM-окон, битовой карты маяков, учёта соседей, управления питанием пиров, детектора плохих
маяков, состояния между интервалами (кроме отсрочки на 1 BI). Всё это в прошивке — надстройка
Wilocity поверх патента.

## 6. Поведенческое следствие схемы
Из правила «отложись, если услышал чужой маяк» следует: в каждом BI маяк передаёт фактически
одна станция — с наименьшей задержкой; остальные молчат. При N узлах каждый маячит примерно раз в
N интервалов (очерёдность через рандомизацию, как в классическом IBSS 802.11), и соседи
обнаруживаются накопительно за много BI. Поле `bcon bitmap` отчёта MAC_MON по смыслу подходит для
такого накопления, но в прошивке 4.1 писателя не имеет
([4.1/docs/UCODE-BEACON.md](https://github.com/klukonin/SparRAW-firmware/blob/main/4.1/docs/UCODE-BEACON.md)).

## 8. Слабое место схемы
Предотвращение коллизий построено на обнаружении чужого маяка. В направленном 60-ГГц канале
соседа слышно, только если на него наведён приёмный луч: «не услышал» ≠ «никто не передавал».
Базовая посылка схемы на mmWave выполняется лишь частично — отсюда коллизии, потери маяков и
компенсирующие механизмы (детектор порогов, счётчики ложных тревог).

## 9. Патентное окружение децентрализованного биконинга

### 9.1 Семейство US8520648B2 — международные аналоги
EP2580878B1, JP5296832B2 / JP2013219817A, RU2541194C2, CN102281088A,
WO2011159404A2, публикация US20110305228A1. Продолжений (continuations), раскрывающих больше,
нет; «Cited By» нерелевантны (Estimote — BLE-маячки для локации, не DMG). ATIM/AW, битовая карта
маяков и учёт соседей этим семейством не покрыты.

### 9.2 Родственный действующий патент US9007967B2
«BSS/PBSS support and schedule-free networking in 60GHz» (= заявка US20140169288A1).
- Изобретатель тот же **Carlos Cordeiro**; приоритет **2009-12-03**, выдан 2015-04-14.
- Статус: действует, истекает 2031-07-30.
- Держатель: **Tahoe Research Ltd** (портфель Intel передан в 2022).
- Суть: биты в Capability Information — тип BSS (Infrastructure / PBSS / **IBSS**:
  B0=0,B1=1) + флаг **«CBP only»** (весь DTT отдан под случайный доступ ⇒
  «schedule-free», не надо парсить Extended Schedule).
- Не раскрывает распределённый биконинг, учёт соседей, ATIM.

### 9.3 Механизмы базового стандарта IEEE 802.11
- **ATIM-окна** — механизм энергосбережения IBSS из базового 802.11 (с 1997).
  `Set new AW. TBTT TSF / tbtt_start_time` в ucode 4.1 — это DMG-адаптация
  стандартного Announcement Window. Не IP Intel.
- **Распределённая генерация маяков в IBSS** — тоже базовый 802.11 (маяк
  разыгрывается между STA со случайной задержкой). Новизна US8520648 была именно
  в направленной адаптации (учёт времени секторной серии в окне конкуренции).

### 9.4 Не найдено в патентах (вероятно, разработка Wilocity)
`bcon bitmap`, учёт услышанных соседей, `bad_beacons_detector` с порогами, `availability_vec`,
векторы энергосбережения пиров. У Wilocity ~25 патентов (портфель перешёл к Qualcomm); поимённо
они не проверены.

### 9.5 Смежные патенты
- **CN113016223B** — «Distributed scheduling protocol with directional
  transmission knowledge» (распределённое планирование с учётом направленности).
- **EP3821664B1** — «Allocation and directional information distribution in
  millimeter wave WLAN networks».
- US9572083B2 — Directional transmission techniques.

### 9.6 Итог по правовому статусу
- Рандомизированная отсрочка маяка свободна (патент прекращён).
- ATIM/AW и распределённая генерация маяков — базовый стандарт, свободны.
- Действующий US9007967B2 касается только сигнализации типа BSS/CBP-only в Capability, права
  держит компания по управлению патентами. Для коммерческого продукта требуется отдельная
  юридическая проверка (включая возможный FRAND-статус, если биты вошли в 802.11ad).
- Это не юридическое заключение: статусы взяты с Google Patents.
